# Release v0.1.28 Design

## Goal

Publish the current `main` branch as `v0.1.28`, including the fixes merged after
`v0.1.27`, without changing runtime behavior beyond those already-reviewed
commits.

## Release Contents

The release is based on commit `b93b62c` and includes the post-`v0.1.27`
changes for root heal task status and beta.9 Admin API response envelopes.

## Version Changes

Update the workspace package version and all three internal workspace dependency
versions in `Cargo.toml` from `0.1.24` to `0.1.28`. Regenerate `Cargo.lock` so the
`rc-core`, `rc-s3`, and `rustfs-cli` package entries are also `0.1.28`.

## Validation

Before committing the version bump, run:

- `cargo fmt --all --check`
- `cargo clippy --workspace -- -D warnings`
- `cargo test --workspace`

The release commit must not be created unless all checks pass.

## Publication

Create the commit `feat(phase-2): release v0.1.28` on
`cxymds/release-v0.1.28`, push the branch, create annotated tag `v0.1.28` at the
release commit, and push the tag. The tag triggers the existing Build and Release
workflow, which verifies the source, builds platform artifacts, creates the
GitHub Release, and publishes crates when registry credentials are available.

## Failure Handling

If local validation fails, stop before committing. If the GitHub workflow fails,
do not move or recreate the published tag; diagnose the failed job and apply a
new corrective commit and version only after review.
